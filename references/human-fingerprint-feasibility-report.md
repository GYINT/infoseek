| 层次 | 资产 | 说明 |

| 发现层 | Maigret / Sherlock | `core/identity_aggregator.py` 双源聚合去重（`CROSS_SOURCE_BOOST=0.10`，交叉确认 +0.10 / 误报抑制 / 分区） |

## 二、三类因子逐项可行性评估

| 因子 | 可行性 | 主要落点 | 重叠度 | 净增量 |
| --- | --- | --- | --- | --- |
| ① 账号本身指纹 | ✅ 可行 | `scripts/account_trust_scorer.py`（四维） | ~75% | 内容伪造特征 ~25% |
| ② 粉丝互动指纹 | ✅ 可行 | `extensions/fake_detect/l1_engine.py` + L2 + `sync_detect.py` | ~70% | 粉丝质量回灌、互动时段熵 ~30% |
| ③a 设备 / 客户端指纹 | ❌ **不可行（红线）** | —（无且不应有） | 0% | ❌ 不落 |
| ③b 机械化行为指纹 | ✅ 可行 | `sync_detect.py` + L1 | ~60% | 时段熵、内容模板化 n-gram、公开客户端标签 ~40% |

### 因子① 账号本身指纹 ✅ 可行

- **子维度**：成熟度 / 规模 / 质量 / 内容 / 行为。
- **既有覆盖**：AccountTrustScorer 四维（成熟度 / 粉丝 / 行为 / 内容）→ **重叠 ~75%**。
- **净增量 ~25%**：资料完整度、用户名模式、bio 模板化、头像复用。
- **落点**：AccountTrustScorer 维度扩展（四维 → 五维）。

### 因子② 粉丝互动指纹 ✅ 可行

- **子维度**：关系结构 / 粉丝质量 / 互动异常 / 增长偏离 / 时间分布。
- **既有覆盖**：FakeDetect L1（关注比 / 互惠率 / 增长导数 / ER 分档）+ L2（Louvain 密度 d>0.25、PPR 种子富集）+ 时序同步 → **重叠 ~70%**。
- **净增量 ~30%**：粉丝质量回灌、互动时段熵。
- **落点**：L1 重参数化 + 粉丝质量回灌通道。

### 因子③ 账号机器指纹 ★ 必须二分

#### 义 1 · 设备 / 客户端指纹 → ❌ 不可行（红线）

UA / 屏幕 / Canvas·WebGL / 字体 / 时区 / JA3·JA4 等——属**在线追踪标识**（不由用户主动发布、不可见、须被动计算）。
与 `PRIVACY.md §4`（不收集设备标识）、`§6`（禁止未经授权的私人追踪 / 规避平台隐私与登录限制）、`network-boundary-report.md §4`（不绕过网络限制）冲突；且与 `scripts/l2_renderer.py` 的**反指纹**方向完全相反。**否决。**

#### 义 2 · 机械化行为指纹 → ✅ 可行

发帖节奏 / 活跃时段熵 / API 调用模式 / 内容模板化 / 协同互惠异常。
采的是「行为像不像机器」（主动观察账号可见行为），而非「设备是什么」（被动计算）。
**既有覆盖**：FakeDetect 时序同步 + L1 增长导数 → **重叠 ~60%**。
**净增量 ~40%**：活跃时段熵、内容模板化 n-gram、公开客户端标签。
**落点**：L1 增列节奏 / 时段熵规则 + L2 内容模板化聚类。

> **关键区分**：义 1 采「设备是什么」（被动计算，红线）；义 2 采「行为像不像机器」（主动观察账号可见行为，安全）。**术语须命名分离**（禁止混用「机器指纹」一词概括两者）。

## 三、合规边界裁决

> 本节收敛自对「设备 / 客户端指纹属账号公域信息、仅用于交叉识别账号潜在关联、不收集存储个人信息」三段式主张的裁决结论。

### 3.1 三段式主张逐条拆解

| 主张 | 裁决 | 理由 |
| --- | --- | --- |
| ① 「账号**公域**信息」 | ❌ 不成立 | 公域判据＝主体**主动向不特定公众发布且他人可见**；设备指纹不由用户发布、不可见、须**被动计算** → 属在线追踪标识（GDPR Recital 30 + 中国《个保法》） |
| ② 「仅用于**交叉识别账号潜在关联**」 | ❌ 反而加重定性 | 准标识符跨账号比对、推断「同一自然人控制多账号」＝用户画像 / 识别自然人，需**单独同意** + 高概率触发 **DPIA**；规制「处理行为」**不以是否存储为界** |
| ③ 「**不收集存储**」 | ❌ 抗辩不充分 | 处理含收集 / 存储 / 使用 / 比对 / 推断；交叉识别产物＝**推断性个人信息**，敏感度更高（`coord_clusters` / `sync_groups` 即此类）；跨账号 / 跨期关联必然需指纹**持留或可比对性**，与「不存储」自相矛盾 |

### 3.2 与 infoseek 现行基线的四处正面冲突

1. `PRIVACY.md §4` 明文把「设备标识」列入**不收集项**；
2. `PRIVACY.md §6` 合法用途边界表**明令禁止**「未经授权的私人追踪」「规避平台隐私 / 登录限制」；
3. `references/network-boundary-report.md §4`「**不绕过网络限制**（无代理 / VPN / 反爬对抗）」，且 FakeDetect / AccountTrustScorer 边界为 `local`；
4. `scripts/l2_renderer.py` 是「**反指纹**」（Camoufox＝反指纹 Firefox 主引擎；`_apply_stealth` 隐藏 webdriver / UA / WebGL / 视口）——四层四维**从未触及设备层**，属**架构层有意规避**。

### 3.3 可接受的边界重构

- 设备 / 客户端指纹 → 只用**账号层面公开可观测特征**；
- persona 归因 → 限**单调研目标内群体级协同簇**（不落到具体自然人）；
- 「不存储」自辩 → 改为**默认 OFF + consent + env + 数据最小化 + 结果脱敏 & audit.log + 不静默伪造**；
- 主动探测 → **唯一可站立形态＝账号自身主动公开发布的设备标签**。

### 3.4 合规检验清单（6 条判据）

① 来源（主体是否主动公开？）② 方式（是否需被动计算 / 主动探测？）③ 目的（是否指向特定自然人？）④ 持留（是否依赖跨期可比对？）⑤ 章程（是否触碰 `§4` / `§6` / network `§4`？）⑥ 边界（是否把 `local` 推向 `open`？）

### 3.5 一句话收口

**目标可行且 FakeDetect 已具备；载体不合法、不合理、与现有防线方向相反。保留目标、替换载体。**

## 五、开发路径与优先级

### P0 — 既有资产补齐（零合规风险，立即实施）

1. AccountTrustScorer 新增「内容伪造特征」子维 → 四维升**五维**；
2. FakeDetect L1 增列活跃时段熵 / 节奏规律 / 内容模板化 n-gram；
3. FakeDetect 粉丝质量回灌；
4. `account_forensics` dataset 增 `profile` / `timing` 字段（**向后兼容**）。

**判据**：仅扩展字段 + 规则，**不新增能力项、不改 network_boundary、不动默认开关**。

### P1 — 协同簇增强 + 融合校准（需真实样本）

1. 复用 `CROSS_SOURCE_BOOST` 语义，把 `coord_clusters` / `sync_groups` 群体置信注入融合 → 因子由 A/B/C **扩为 A/B/C/D**（D = 协同簇强度）；
2. 权重校准（现 `INFOSEEK_FUSION_WEIGHTS=0.35,0.40,0.25`，四因子须**动态重归一化**）；
3. 误报率基线 **FPR ≤ 2%** + `train_l1_thresholds` 校准 `l1_thresholds.json`。

**判据**：守护断言覆盖「缺因子降级不中断」「权重非法回退默认」。

### P2 — 设备层窄口（暂缓）

- 仅「**账号自身主动公开发布的设备标签**」作弱证据；
- **前置硬性条件**：修订 `PRIVACY.md §4` + 重评 `network_boundary` + 6 条合规模板全通 + 用户显式授权。
- **当前建议：不实施**，仅登记「红线内候选」。

### 5.5 验收判据

- 合规三重闸 + audit.log + 不静默伪造；
- FPR ≤ 2%；
- 73 套件全绿；
- 本阶段**维持 v2.2.0**。

### 5.6 ROADMAP 登记

建议纳入 P0 / P1 并标注「评估结论 + 红线边界」；P2 **仅登记不排期**（见 `references/ROADMAP.md` 人因指纹增强条目）。

## 七、结论与建议

1. **目标可行**——识别水军 / 机器人集群、账号潜在关联，FakeDetect 取证链已具雏形；
2. **载体须换**——设备 / 客户端指纹是红线，**否决**；① ② 与「机械化行为指纹」可行；
3. **① ② 可行且高重叠**（~75% / ~70%）——增量靠**既有资产补齐**，非另起体系；
4. **③ 须二分**——设备层否决、行为层可行，术语命名分离；
5. **优先 P0**——零合规风险，先扩字段与规则；
6. **合规闸不放宽**——`enabled:false ∩ consent ∩ env` 三重闸照旧，版本维持 v2.2.0。
