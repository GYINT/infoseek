## 1. 四层退化量化口径与结果

| 层 | 退化现象 | 量化判据（验收门） | 样本 | 结果 |
|----|----------|--------------------|------|------|
| A 召回退化 | 长尾中文在通用/国际引擎召回为空/质量差 | 长尾 query 默认层首位 == CN-AI-Web；实例唯一；保留通用引擎兜底 | 3 长尾 ×3 断言 | 全过 |
| B 召回增强零增益 | 提权未带来融合增益 | CN 融合权重 0.3→1.0 且 ≤ 封顶 1.0；Bing-RSS 基线 0.9 不变；`_merge_diverse` 排序 CN 居首 | 6 权重 + 1 基线 + 1 排序 | 全过 |
| C 过滤门控误杀 | 短中文/正常 query 被误判长尾而误路由 | 短中文/英文：不前置 CN、权重保持 0.3、`_longtail_cn` 为 False | 3 短中文 + 2 英文 ×3 | 全过 |
| C+ 开关回退 | 提权误开时无法关闭 | `INFOSEEK_CN_PRIORITY=0`：CN 回末尾、权重回落 0.3 | 3 长尾 ×2 | 全过 |
| D jieba 缺失回退 | 无 jieba 时长尾判定/路由崩 | 屏蔽 jieba 后仍判长尾、仍前置 CN（纯 re 路径独立） | 3 长尾 ×2 | 全过 |
| D+ CN4 netguard | 端点全挂/探测异常时污染主链 | 全不可达→返 []；探测异常→保守保留全部且不崩 | 2 | 全过 |

合计 **46 PASS / 0 FAIL**。

## 2. 离线 fixture 说明

- 不触网：`net_probe.check_hosts` 用桩（全 False / 抛 RuntimeError），`_http_get` 桩抛异常。
- 环境隔离：用例启动清空全部 `INFOSEEK_` env，避免 per-capability 旁路污染默认态；C+ 用例自管开关并在结束清理。
- query fixture：
  - 长尾（CJK 字数 ≥6）：「信阳板栗今年产量是多少？」等 3 条，覆盖农业/新能源/医改长尾。
  - 短中文：「股票/苹果/量化」；英文：2 条。

## 3. 边界与后续

- 本基准验证的是**路由/权重/排序/兜底的内部契约**，不代表真实网络下 CN-AI-Web 的召回质量
  （真实质量受沙箱网络限制，已在 CN4 netguard 做边界兜底）。
- 后续若环境放开，可在此基准补「真实端点 A/B 命中率」维度，台账增量登记，不替换离线口径。
