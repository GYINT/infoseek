## 1. GA11 · 段落级事实槽重构

### 1.1 问题实锤

| 证据 | 来源 |
|---|---|
| 12 组声明对（含 4 组已知真实口径差异）→ **12/12 `severity=none`**、`slot_score` 恒 0、`shared_slots` 全空 | ROADMAP §8.11.1 D3（2026-09-13 人物类调研实测，谢博文/项林坚履历验证） |
| 对**短句 / 极性对立**有效（否定词、反义对命中） | 同上（`_detect_negation` 路径工作正常） |
| 结论：段落级语料矛盾召回**近零**，必须人工事实槽对齐补位 | ROADMAP §8.11.1 |

### 1.2 代码级根因（读 `core/contradiction_scorer.py` 实锤，非推测）

```
_extract_slots(text)            # L74：谓词模板命中 → (predicate,value) 短语；
                                #      兜底：对**全文**滑窗 2-gram，过滤停用 bigram
score_contradiction(a, b)       # L144
  shared = slots_a & slots_b    # L158：集合交集
  jaccard = |shared| / |union|  # L160
  slot_score = int(jaccard*30)  # L161 ← 结构性缺陷所在
  total = slot_score + neg_score              # L165
  if len(shared) >= 2 and neg>0: ×1.4         # L167-169 ← 依赖 shared，级联失效
  ≥60 high / ≥30 medium / ≥10 low / else none # L171-178
```

四个结构性缺陷（按影响排序）：

1. **口径错配（根本）**：Jaccard 测的是「集合**相似度**」，而矛盾判定需要「同一槽位键上的**值冲突**」（keyed comparison）。二者不是同一问题：
   - 相似度高 ⇏ 矛盾（同义复述、转载源 → 高相似但完全一致）；
   - 相似度低 ⇏ 不矛盾（长文表述差异大但核心事实相反）。
2. **长文本稀释（直接致因）**：兜底 2-gram 对**全文**滑窗 → 文本越长，`union` 越大、交集概率越低 → `jaccard→0`。段落级（数百字）实测必然归零。
3. **槽未归一化**：不同表述的同一谓词（「营收增长 12%」vs「收入同比上升 12%」）不会映射到同一槽键 → 即使都命中模板也进不了 `shared`，交集恒空。
4. **级联失效**：③ 极性放大（×1.4，本用于「同一主题不同观点」经典模式）以 `len(shared) ≥ 2` 为前置 → 长文本下 `shared≡0` → 放大永不触发，进一步压低总分。

> **关键判断**：这不是「调阈值/加模板」能修的（缺陷 1/2 是表示层问题），而需**更换事实槽的表示与比对方式**。

### 1.3 方案选型

#### 方案 A · 结构化事件槽对齐（推荐基线；零依赖）

```
每条 claim → 归一化槽表 {slot_key: value}
  slot_key = (主体规范化, 谓词规范化, 期间/时间)
  value    = 数值 | 极性(+/-) | 枚举字面
比对：键交集（同键）→ 值冲突判定
  数值差异 > 阈值（相对/绝对）| 极性相反 | 枚举互斥 → 冲突槽
severity 由冲突槽数量 + 冲突强度驱动（与现有 score→severity 映射兼容）
```

- **谓词同义归一表**（新增数据真源，如 `references/contradiction-synonyms.json`）：
  营收/收入/营业额 → `revenue`；增长/上升/提升/增加 → `rise`；下滑/下降/降低/减少 → `fall`；……
- 与现有 zero-dependency 哲学一致；确定性、可复现、可单测。
- **代价**：覆盖面受模板/同义词表限制 → 设「未命中即回落现值」的降级（宁缺勿错）。

#### 方案 B · LLM 辅助槽抽取（opt-in 增强）

- 复用既有 `llm_router`（多 provider + 成本折算已就绪，`score_with_llm` L196 已有骨架）：
  prompt 要求输出 **JSON 槽表**（固定 schema）→ **复用方案 A 的键控比对层**（比对逻辑不重复实现）。
- 覆盖长叙述句与隐含语义（A 的短板）；成本可控（仅对候选对调用 + 结果缓存）。
- **代价**：token 成本；非确定性 → 需 温度 0 + 结果缓存（键=两文本哈希）+ 双跑一致性校验；需 key（无 key 自动回落）。

#### 方案 C · 混合分层（推荐最终形态）

```
A 为默认路径（零依赖可用）
B 为 opt-in（env: INFOSEEK_CONTRADICTION_LLM=1，需 key）
降级链：B 不可用 → A → 现值（v2.4.x 行为）
```
- 与 infoseek 既有「所有增强均有降级路径」设计哲学同构（见 SKILL.md 设计边界）。

### 1.4 验收设计（可测判据 — 立项后即按此验收）

| 判据 | 方法 | 门槛 |
|---|---|---|
| 段落级改善 | 12 组段落语料（含 4 组已知真实口径差异）重跑 | ≥8/12 判出 `low` 以上，其中 4 组真实差异 ≥`medium` |
| **短句零回归** | 现有短句/极性对立断言全量复跑 | 全绿（现有 `severity` 判定不变） |
| 长文本不稀释 | 同语义 100 字 vs 300 字改写 → 同判 | 判定一致（现实现必不一致） |
| 契约向后兼容 | `score_contradiction` 入参/出参 schema | 老字段语义不变，仅新增字段 |
| 新增守护 | `tests/test_contradiction_paragraph_v2x.py`：键控对齐单测（同键冲突/同键一致/异键）+ 稀释回归 | 全绿 |
| 误报控制 | 一致语料（同义复述/转载）不得被判 `medium` 以上 | 误报率 ≤ 现状 |

### 1.5 工作量、风险、边界

- **工作量**：A ≈ 400-600 行（槽抽取 + 同义表 + 键控比对）+ 测试 ~200 行；B ≈ +200 行（prompt + JSON 解析 + 缓存 + 双跑校验）；C = A+B（推荐终态）。
- **风险**：①同义词表覆盖天花板 → 用「可配置 + 未命中回落」缓解；②LLM 非确定 → 温度 0 + 缓存 + 双跑校验；③长文本判出更多冲突 → **须保留人工事实槽对齐补位**（§8.11.1 已明示「不可依赖自动检测器」）。
- **明确不做**：不引入重型 NLP 依赖（spaCy/transformers 等）以守零依赖边界；不做全自动「事实裁决」（只做冲突**标记**，不做真伪判定）；不改动 `conflict_v3` 的 claim 抽取契约（只换评分层）。

## 2. GA12 · 目标机闭环（网络边界探测门控）

### 2.1 问题实锤

| 证据 | 来源 |
|---|---|
| Wikidata / Wikimedia 全系不可达（DNS 解析到污染 IP + https 黑洞；http 301 / https 超时） | ROADMAP §8.15 / §8.12.2 GA12 |
| `github.com` 大文件传输不可达（~37KB/s 或超时）；`storage.googleapis.com` 不可达 | 同上 |
| Google Patents 单专利页/搜索页返回 `Resource does not exist.`（SPA 需 JS） | 同上 |
| 特征：**DNS 可解析但返回污染 IP**（wikidata→103.102.166.224）；对照仅 `mirrors.cloud.tencent.com` / `cn.bing.com` 可达 | 同上 |
| 后果：依赖这些 host 的能力在沙箱**静默失败或长超时**，无显式「环境受限」声明 | 本简报勘查 |

### 2.2 现有设施盘点（可复用，非从零）

| 设施 | 位置 | 现状 | 缺口 |
|---|---|---|---|
| `probe_http(url, timeout)` | `engine_router.py:92` + `search_engine_health.py:37` | **两处重复实现** | 需单源化（第三份重复风险） |
| 能力注册表 | `capabilities/registry.yaml`（6.6KB）+ `capability_registry.py` | 有 `kind` / `env_var` / default_off | **无网络边界声明**（不知道某能力依赖哪些 host） |
| 镜像重写 | `scripts/mirror_map.py`（策略①A：不可达域名→可达镜像） | 已覆盖**抓取层** | 未覆盖能力级「能否运行」判定 |
| 引擎健康状态机 | `engine_lifecycle.py` | 有失败计数/熔断 | 面向引擎，非面向能力-host |

### 2.3 方案

```
① probe_http 单源化      → 抽 scripts/net_probe.py（TTL 缓存 + 幂等），两处委托，删除重复实现
② registry.yaml 声明扩展 → 每能力新增 requires_hosts: [...] + network_boundary: open|sandbox_restricted
③ 新增 scripts/boundary_gate.py
     available(capability) → 按声明探测所需 host（TTL 内复用缓存）
     不可达 → 返回受限原因 + 走显式降级（而非静默失败/长超时）
④ 受限清单生成           → references/network-boundary-report.md
     （沙箱内可生成；目标机重跑即刷新，形成「沙箱 vs 目标机」对照）
⑤ 默认 off 收敛          → 已知沙箱不可达 host 的能力，沙箱内自动进入受限降级路径
```

- 设计原则：**不尝试绕过网络边界**（不做代理/VPN/反爬对抗——违反 SKILL.md 设计边界）；**不把受限能力伪装为可用**（显式声明 + 留痕）。
- 与既有降级哲学同构：能力不可用 → `degrade_to` 链 → 显式「受限说明」（参考 `capability_compensator.py` 的 `trail` 机制）。

### 2.4 验收设计

| 判据 | 沙箱内可验 | 目标机补验 |
|---|---|---|
| 探测门控单测（mock 可达/不可达/超时/DNS 污染） | ✅ | — |
| `registry.yaml` 声明完整性校验（每能力 host 非空 / 枚举合法） | ✅ | — |
| 受限降级路径留痕（日志 + 审计字段） | ✅ | — |
| 受限清单生成与格式校验 | ✅ | — |
| **真实可达性判断准确性** | ⚠️ 仅能以已知不可达 host 做**负向**验证 | ✅ 正向验证（目标机真实网络） |
| 全量回归零回归（默认 off ⇒ 行为不变） | ✅ | — |

### 2.5 工作量、风险、边界

- **工作量**：≈ 300-450 行 + 测试 150 行；**风险低**（防御层；`default_off` ⇒ 既有行为零变更）。
- **风险**：①探测本身引入网络延迟 → TTL 缓存 + 超时上限 + 默认 off 缓解；②沙箱内无法正向验证可达性 → 以「负向验证 + 目标机补验清单」显式标注，不冒充已验。
- **明确不做**：不绕过网络限制；不将受限项标记为「通过」；不改动既有能力默认开关语义（只加声明与门控）。

## 3. 立项建议

1. **顺序**：GA12 先（低风险、沙箱可全量自测、零行为变更、且能立刻为「沙箱 vs 目标机」差异建立可复现台账）→ GA11 后（深水区，需先确定 A/B/C 方案与制备段落语料）。
2. **合并机会**：GA12 与 §6.3 的 **G6（Sherlock 运行实证）/ G7（L3 真实凭证冒烟）** 同属「环境受限 / 需目标机闭环」族，建议并为**一次「受限能力治理」立项**统一处理，避免三次分散勘界。
3. **依赖**：GA11-B 需 LLM key（`llm_router` 已支持多 provider）；GA12 无新依赖。
4. **版本**：GA11 若变更判定口径 → **v2.0.0（MAJOR）**；若保持老字段语义仅增量 → v2.1.0。GA12 → MINOR。
5. **前置门槛**（立项时须满足）：现基线全量回归绿（当前 **57 PASS / 0 FAIL** ✅）+ 选定方案 + 语料/验收判据确认。
